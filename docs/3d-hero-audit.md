# Аудит 3D-hero перед переработкой

Снято 2026-08-06 на продакшен-сборке (`next start`), Chromium под SwiftShader.
Скриншоты: [`research/3d-hero/before/`](../research/3d-hero/before/).

## Что есть сейчас

| Файл                                         | Строк | Роль                                                                                                            |
| -------------------------------------------- | ----- | --------------------------------------------------------------------------------------------------------------- |
| `src/features/hero-scene/index.tsx`          | 15    | динамический импорт, `ssr: false`                                                                               |
| `src/features/hero-scene/HeroCanvas.tsx`     | 183   | жизненный цикл: WebGL-проверка, отсев слабых устройств, IntersectionObserver, visibilitychange, pointer, scroll |
| `src/features/hero-scene/GreySignalScene.ts` | 359   | вся сцена одним классом: renderer, камера, три объекта, цикл, адаптация качества                                |
| `src/features/hero-scene/shaders.ts`         | 249   | симплекс-шум, шейдеры массы и частиц                                                                            |

Стек: чистый three.js 0.185 без React Three Fiber. Постобработки нет.
`motion` используется в интерфейсе, но не в сцене.

Композиция: икосаэдр радиусом 1.55 с доменно-искажённым шумом, вокруг —
точечные частицы (260/620/1100), сбоку — четыре дуги `LineSegments` («усы»).
Освещение считается вручную в фрагментном шейдере: две направленные лампы,
Блинн-Фонг и френель.

## Что работает хорошо и должно остаться

- **Разделение ответственности.** Сцена не знает про React, обёртка не знает про
  WebGL. Это верная граница, её нужно сохранить.
- **Отложенный запуск.** Загрузка после `load` + `requestIdleCallback`, постер
  рендерится сервером с `priority`. LCP не зависит от сцены — менять нельзя.
- **Пауза вне вьюпорта и при скрытой вкладке.** IntersectionObserver +
  `visibilitychange` — реализовано верно.
- **Понижение качества по факту.** Средняя стоимость кадра за 90 кадров, а не
  угадывание GPU по строке рендерера. Идея правильная, но реагирует только один
  раз и только понижением DPR.
- **Обработка `webglcontextlost`** и полный `dispose()` геометрий и материалов.
- **Собственный симплекс-шум и ручное освещение** — дешевле PBR и даёт контроль.

## Что выглядит слишком просто

1. **Это «distortion sphere».** Ровно тот силуэт, который встречается в сотнях
   Three.js-демо: шар, продавленный шумом. Собственной идеи в форме нет.
2. **Объект занимает пол-экрана.** Радиус 1.55 при камере на 6.2 — масса
   доминирует и спорит с заголовком, вместо того чтобы поддерживать его.
3. **Сигнал читается как краска.** Полоса задана гауссианой по `displaced.y`,
   то есть это широкая горизонтальная лента. На скриншоте — зелёная шапка на
   верхней трети объекта. Метафора «тихий сигнал» не считывается: акцента много
   и он статичен по форме.
4. **Гранёная поверхность.** Нормаль пересчитывается численно с `eps = 0.02`, и
   на подразделении 5 грани икосаэдра видны как фасетки. Форма выглядит
   каменной, а не металлической.
5. **Частицы почти не видны** и движутся броуновским шумом — ни орбит, ни
   структуры. Ощущения данных нет.
6. **«Усы» живут отдельно от объекта.** Четыре статичные дуги в стороне, не
   реагируют ни на курсор, ни на прокрутку — только вращаются вместе с массой.
7. **Фон пустой.** Чистая прозрачность поверх плоского градиента секции, без
   глубины, тумана и светового пятна за объектом.
8. **Реакция на курсор сводится к повороту.** `rotation = pointer * 0.32`
   со сглаживанием 0.045 — инерция есть, но локального отклика на поверхности,
   отклонения частиц и изменения света нет.
9. **Нет состояний.** Ни вступления, ни реакции на CTA, ни осмысленного перехода
   при прокрутке: объект просто уезжает вглубь и уменьшается.
10. **Постоянное вращение** `idle * 0.045` по Y — то самое «бесконечное
    вращение модели», которого просили избегать.

## Замеры

- Ошибок в консоли нет ни на десктопе, ни на мобильном (проверено Playwright,
  слушатели `console` и `pageerror`).
- Под SwiftShader кадр стоит порядка 40–60 мс — это программный растеризатор
  песочницы, к реальному железу отношения не имеет. Оценивать FPS по этой среде
  нельзя, и в отчётах он не приводится.
- На мобильном (390×844, `pointer: coarse`) сцена по текущим правилам
  **не запускается вовсе** — виден только постер. Скриншот `mobile-390-idle.png`
  это подтверждает.

## Риски переработки

| Риск                                                | Мера                                                                                                          |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Рост стоимости кадра из-за нескольких проходов шума | Один общий блок шума, не больше двух октав, орбиты частиц считаются поворотом вокруг оси, а не шумом          |
| Прозрачные линии и частицы дают overdraw            | `depthWrite: false`, аддитивное смешивание только для частиц, линии — тонкие и малочисленные                  |
| Больше объектов → больше draw call                  | Шесть объектов суммарно: ядро, частицы, усы, хвост, сетка, фон. Инстансинг не нужен — частицы и так один `Points` |
| Сцена перетянет на себя внимание с текста           | Объект уменьшается, уходит вправо, акцентный цвет ограничен долей поверхности                                 |
| Мобильные GPU не тянут displacement                 | Отдельный уровень качества: меньше подразделений, без сетки, упрощённый шейдер                                |
| Регресс LCP                                         | Порядок загрузки не меняется: постер сервером, сцена после `load`                                             |

## Что меняется, что остаётся

**Остаётся:** структура «класс сцены + React-обёртка», отложенный запуск,
постер, паузы, обработка потери контекста, адаптация качества по стоимости
кадра, собственный шум.

**Меняется:** форма и материал ядра, поведение частиц, роль линий, фон,
реакция на курсор, состояния CTA, сценарий прокрутки, разбиение на файлы.
