# Модель контента

Схема описана кодом в `src/collections/` и `src/globals/`. Типы генерируются
командой `pnpm generate:types` в `src/payload-types.ts` — вручную их не правят.

## Коллекции

### `cases` — Кейсы

Основная коллекция. Черновики включены, история версий — до 20 на документ.

**Обзор:** `title`, `client`, `shortDescription`, `shortResult`, `cover*`,
`heroMedia`, `tags[]`.

**Рассказ:** `challenge`, `context`, `solution`, `process`, `results` (rich text,
все опциональны) и `contentBlocks` — свободная часть страницы.

**Результаты и команда:** `metrics[]` (значение, что измеряли, как измеряли),
`testimonial` (текст, автор, должность, фото), `projectTeam[]` (связь с
командой либо внешнее имя + роль), `relatedCase`, `externalUrl`.

**Боковая панель:** `slug*`, `year*`, `services[]`, `categories[]`, `featured`,
`sortOrder`, `publishedAt`, `_status`.

**SEO:** `seo.title`, `seo.description`, `seo.image`, `seo.noindex`.

Поведение:

* slug генерируется из названия с транслитерацией кириллицы, редактируется вручную,
  уникален, проверяется по формату;
* `publishedAt` проставляется автоматически при первой публикации;
* сортировка: `sortOrder` по возрастанию, затем `publishedAt` по убыванию;
* `afterChange` сбрасывает кеш `/`, `/cases`, `/cases/[slug]` и `sitemap.xml`;
* превью и live preview ведут на `/preview` с проверкой секрета и сессии.

### `services` — Услуги

`title*`, `promise*`, `shortDescription`, `fullDescription`, `clientProblems[]`,
`scope[]`, `deliverables[]`, `relatedCases[]`, `ctaLabel`, `ctaHref`,
`slug*`, `stage*`, `icon`, `visual`, `sortOrder`, `published`, `seo`.

`stage` — этап жизненного цикла: `research`, `design`, `development`, `growth`,
`ai`. Группировка на сайте идёт по нему; пустые этапы не выводятся.
Этап «AI и автоматизация» включайте только если это реальная услуга студии.

### `categories` — Категории

`title*`, `slug*`, `description`, `sortOrder`. Используются фильтром на `/cases`.

### `team` — Команда

`name*`, `slug*`, `role*`, `photo`, `shortBio`, `extendedBio`, `quote`,
`links[]`, `sortOrder`, `published`.

Имя, роль и биография — редактируемые поля. В коде они не зашиты.

### `media` — Медиа

`alt`, `decorative`, `caption`, `credit` + системные поля файла.

* Разрешённые типы: JPEG, PNG, WebP, AVIF, SVG, MP4, WebM. Максимум 25 МБ.
* Автоматические размеры: `thumbnail` 400×400, `card` 768×576, `portrait` 800×1000,
  `wide` 1600, `hero` 2400, `og` 1200×630. Загруженное конвертируется в WebP.
* `alt` обязателен для изображений; для фона и текстур отмечайте «Декоративное» —
  тогда `alt=""` и скринридер их пропускает.
* Включены focal point и кадрирование.

### `enquiries` — Заявки

`name*`, `contact*`, `company`, `budget`, `message*`, `status`, `consent`,
`meta.sourcePage`, `meta.userAgent`.

Создаются **только** серверным экшеном формы. Публичного `create` через
REST/GraphQL нет. Читают и меняют статус admin и editor, удаляет — admin.

### `users` — Пользователи

`email` (auth), `name*`, `role*` (`admin` | `editor`), `active`.

* В админку пускаются только активные пользователи с ролью admin или editor.
* Поля `role` и `active` доступны на запись только администратору.
* Редактор видит и правит только свою запись.
* Блокировка после 8 неудачных попыток входа на 10 минут.

## Глобальные настройки

### `site-settings` — Настройки сайта

* **Первый экран:** название студии, заголовок, подзаголовок, уточнение,
  две кнопки (текст + ссылка).
* **О студии:** позиционирование, принципы работы, шаги процесса.
* **Контакты:** заголовок и текст блока, email, Telegram, телефон, город,
  ссылки на площадки. Пустые поля не выводятся на сайте.
* **Футер и право:** текст футера, юридическое наименование, правовые ссылки,
  текст согласия в форме.
* **SEO и аналитика:** SEO по умолчанию, описание организации для Schema.org,
  идентификатор Яндекс Метрики.

### `navigation` — Навигация

Пункты шапки (до 6), кнопка в шапке, группы ссылок футера (до 4).
Меняются без правки кода.

## Блоки страницы кейса

Небольшая типизированная система вместо универсального page builder.

| Блок | Назначение |
| --- | --- |
| `richText` | Текст с надзаголовком и заголовком, узкая или полная ширина |
| `fullWidthImage` | Изображение во всю ширину, с подписью, опционально до краёв экрана |
| `imagePair` | Два изображения рядом, три варианта пропорций |
| `gallery` | Сетка изображений в 2 или 3 колонки |
| `video` | Видео с **обязательным** постером; автозапуск без звука опционален |
| `quote` | Цитата с автором и должностью |
| `metricGrid` | Сетка показателей; поле «как измеряли» у каждого |
| `textMedia` | Текст с изображением слева или справа |
| `stickyText` | Закреплённый заголовок + пронумерованные шаги |
| `nextCase` | Переход к следующему проекту |

## Принципы модели

1. **Все секции опциональны.** Пустое поле в CMS не создаёт пустой блок на
   странице: компоненты проверяют содержимое (`hasRichTextContent`, длина массивов).
2. **Никаких выдуманных данных.** Метрики требуют пояснения методики, отзывы
   публикуются только реальные, названия клиентов — только с их согласия.
   Соответствующие подсказки выведены прямо в интерфейс админки.
3. **Тексты — в CMS, не в коде.** Всё, что видит посетитель на первом экране,
   в блоке контактов и в футере, редактируется без разработчика.
4. **Черновик не виден публично.** Контроль доступа `publishedOrEditor` для
   версионируемых коллекций и `publishedFlagOrEditor` для остальных.
