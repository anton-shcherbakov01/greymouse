# Grey Signal — концепция сцены

Технический план переработки первого экрана. Аудит того, что было, —
в [`3d-hero-audit.md`](./3d-hero-audit.md).

## Идея

> Пока другие создают шум, «Серая Мышь» превращает едва заметный сигнал
> в работающий цифровой продукт.

Сцена показывает не объект, а **процесс**: рассеянные частицы собираются в
плотную форму, сквозь неё проходит сигнал, при уходе со страницы форма снова
распадается на частицы и уводит их к следующей секции.

Ассоциация с мышью держится на силуэте и поведении, а не на морфологии:
приплюснутая капля, две едва намеченные доли сверху, тонкие боковые линии,
длинная траектория позади. Ни одна из этих деталей по отдельности не читается
как «ухо» или «хвост» — они работают вместе и не сразу.

## Композиция

```
                  ┌─ сетка (импульсами)
                  │
        «усы»     │        SignalParticles (орбиты)
        ╲         │       ·  ·   ·
     ────╲──      ▼    ·           ·
   ───────╲──  ╭──────╮   ·
              │ Core │        ·        ← GreySignalCore
   ───────╱── ╰──────╯   ·
     ────╱──        ·   ·
        ╱      ╲__________________ хвост-траектория
                                        (уходит вниз-назад)
              HeroBackdrop: световое пятно, туман, пыль
```

Ядро смещено вправо и вверх на десктопе, вверх по центру на мобильном —
чтобы не спорить с заголовком. Размер уменьшен с радиуса 1.55 до 1.0:
объект должен поддерживать текст, а не перекрикивать его.

Сдвигается не камера, а общая группа сцены. Камера смотрит в начало координат,
и её смещение `lookAt` компенсирует — при первой сборке композиция из-за этого
не менялась вовсе. Мобильная раскладка вдобавок уменьшает группу до 0.58:
кадр там узкий, и объект в треть высоты перекрывал экран целиком.

## Объекты

| Объект            | Геометрия                        | Материал                                                       |
| ----------------- | -------------------------------- | -------------------------------------------------------------- |
| `GreySignalCore`  | икосаэдр 1.0, подразделение 4–6  | свой шейдер: displacement + ручное освещение + контурные линии |
| `SignalParticles` | `Points`, 220–900 точек с ролями | свой шейдер: орбиты, отталкивание от курсора, поток к CTA      |
| «усы»             | `LineSegments`, 2×2–3 линии      | `SignalLines`: изгиб к курсору, бегущий импульс                |
| хвост             | `LineSegments`, одна кривая      | тот же `SignalLines`, другие параметры                         |
| сетка             | `LineSegments`, дуги и радиусы   | тот же `SignalLines`, видимость по импульсу                    |
| `HeroBackdrop`    | плоскость на заднем плане        | радиальный градиент + виньетка + дизеринг                      |

## Форма ядра

Три слагаемых поверх сферы:

1. **Крупная пластика** — доменно-искажённый симплекс-шум, амплитуда 0.065.
   Медленная, период порядка 20 секунд. Даёт «живой металл», а не резину.
2. **Силуэт** — сжатие по вертикали, вытягивание по −Z (капля), две мягкие доли
   в верхней части на ±35° от вертикали. Постоянная составляющая, не анимируется.
3. **Локальная волна от курсора** — гауссиана вокруг направления на указатель,
   затухающая за 0.6 с после остановки.

Нормаль считается численно по двум соседним точкам, как и раньше, но `eps`
уменьшен и завязан на подразделение — фасетки на скриншотах были от него.

## Сигнал

Отказ от горизонтальной полосы. Вместо неё:

- **контурные линии** — изолинии того же шумового поля, что задаёт форму:
  `abs(fract(field * 3 - t) - 0.5)`. Очень слабые, дают ощущение
  просканированной поверхности;
- **одна бегущая линия** — узкая, проходит по объекту снизу вверх раз в ~9 секунд
  и на событиях (наведение на CTA, импульс сетки);
- акцентный цвет занимает не более ~12 % площади объекта в любой момент.

## Состояния

```
intro → idle ⇄ pointer ⇄ cases-hover / contact-hover
          ↕
      scrolling → dissolved
```

Все переходы — демпфированные скаляры, а не переключатели: каждое состояние
имеет вес 0…1, шейдеры смешивают их. Отдельных сцен на состояние нет.

| Состояние       | Что происходит                                                                                                                 |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `intro`         | 2.2 с: частицы стягиваются из объёма, ядро проявляется по `uReveal`, в конце один световой импульс и вспышка сетки             |
| `idle`          | дыхание амплитуды, дрейф камеры ±0.06, орбиты частиц, изгиб хвоста, редкий проход сигнала                                      |
| `pointer`       | поворот к курсору с инерцией, параллакс камеры, локальная волна, отталкивание ближних частиц, изгиб усов, +9 % к свету         |
| `cases-hover`   | частицы вытягиваются в поток вниз, ядро смещается к секции кейсов, импульс идёт от ядра вниз                                   |
| `contact-hover` | ядро «раскрывается» (френель и внутреннее свечение растут), частицы подтягиваются к центру, сцена теплеет                      |
| `scrolling`     | камера приближается, ядро растворяется по порогу шумового поля, частицы вытягиваются вниз, край растворения подсвечен акцентом |
| возврат вверх   | те же демпферы в обратную сторону; `uReveal` остаётся 1, вступление не повторяется                                             |

## Связь с интерфейсом

Состояние CTA приходит не через `querySelector`, а через маленький модульный
стор `heroInteractionStore`: кнопки первого экрана — клиентский компонент,
он сообщает `cases` / `contact` / `null`, сцена подписывается. React-состояние
при этом не меняется — перерисовки нет, значение читает игровой цикл.

## Уровни качества

|                    | high            | medium   | low      |
| ------------------ | --------------- | -------- | -------- |
| подразделение ядра | 6               | 5        | 4        |
| частиц             | 900             | 520      | 220      |
| усов на сторону    | 3               | 3        | 2        |
| сетка              | да              | да       | нет      |
| контурные линии    | да              | да       | нет      |
| максимум DPR       | 1.75            | 1.5      | 1.25     |
| фон                | градиент + пыль | градиент | градиент |

Уровень выбирается по числу ядер, типу указателя и ширине экрана, затем
корректируется по фактической стоимости кадра: дороже 24 мс в среднем за 90
кадров — ступень вниз (можно дважды, до `low`), стабильно дешевле 10 мс —
одна ступень вверх, но не выше исходной.

## Мобильная версия

Не уменьшенный десктоп: объект меньше и поднят над текстом, частиц меньше,
амплитуда деформации ниже, реакции на указатель нет (её там нет физически),
переход при прокрутке проще — только растворение без потока частиц. Усы
остаются: это узнаваемая деталь.

Сцена запускается и на телефонах — но только на уровне `low` и только если
устройство не отсеяно по памяти. Раньше она там не запускалась вовсе.

## Reduced motion и fallback

`prefers-reduced-motion: reduce` — ровно один отрисованный кадр собранной
композиции: ядро на месте, частицы на орбитах, усы без импульсов. Цикл
анимации не запускается вовсе, поэтому не тратится и заряд.

Без WebGL — постер, отрисованный из этой же сцены, плюс серверный градиент.
Текст и кнопки работают всегда: они обычный HTML вне canvas.

## План файлов

```
src/features/hero-scene/
  index.tsx                     динамический импорт
  HeroCanvas.tsx                React-обёртка: жизненный цикл
  heroInteractionStore.ts       состояние CTA между DOM и сценой
  GreySignalScene.ts            оркестратор: renderer, камера, состояния, цикл
  quality.ts                    уровни качества и адаптация
  types.ts                      типы состояний и контекста кадра
  objects/
    GreySignalCore.ts
    SignalParticles.ts
    SignalLines.ts              усы, хвост и сетка — один класс, три набора данных
    HeroBackdrop.ts
  shaders/
    noise.ts                    общий симплекс-шум
    core.ts  particles.ts  lines.ts  backdrop.ts
```

Отдельных классов `DigitalWhiskers`, `SignalTrail` и `SignalGrid`, намеченных
в первом варианте плана, не появилось: у всех трёх совпадают материал, набор
uniform-переменных и логика обновления — различаются только геометрия и
несколько чисел. Три почти одинаковых класса были бы хуже одного с параметрами.

Постер снимается из самой сцены скриптом `scripts/hero-poster.mjs` —
иначе при отказе WebGL пользователь видел бы композицию предыдущей версии.
