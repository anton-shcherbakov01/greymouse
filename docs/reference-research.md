# Исследование референсов

Документ фиксирует результат Этапа 2. Все выводы получены из фактических прогонов
headless Chromium (Playwright) и разбора DOM/CSS/заголовков ответов, а не по памяти
о том, как выглядят эти сайты.

## Как проводилось исследование

**Инструмент:** Playwright 1.62 + Chromium 141 (`scripts/research-references.mjs`).
Для каждого сайта снималось:

* `desktop-hero.png` — первый экран, 1440 × 900;
* `desktop-mid.png`, `desktop-lower.png` — 35 % и 75 % высоты страницы;
* `desktop-fullpage.png` — вся страница после полной прокрутки;
* `desktop-hover.png` — состояние при наведении на первую карточку/ссылку;
* `mobile-hero.png`, `mobile-fullpage.png`, `mobile-menu.png` — 390 × 844, DPR 2, touch;
* `desktop-reduced-motion.png` — контекст с `prefers-reduced-motion: reduce`;
* `desktop-nojs.png` — контекст с отключённым JavaScript.

Параллельно собирались технические признаки (`research/references/signals.json`):
загруженные скрипты, заголовки ответа, глобальные объекты `window`, размеры и тип
контекста `canvas`, CSS-переменные `:root`, вычисленные размеры/начертания/трекинг
заголовков, наборы `transition-duration`/`timing-function`, количество `position: sticky`
и `mix-blend-mode`, размер DOM.

### Ограничения окружения — что честно не удалось

1. **TLS.** Исходящий HTTPS в песочнице идёт через MITM-прокси, который сбрасывает
   TLS 1.3 handshake от Chromium (проверено: curl работает, браузер — нет, ни один
   флаг TLS/PQC не помог). Шесть сайтов исследованы с `--ssl-version-max=tls1.2`.
   `gravity.nl` принимает только TLS 1.3, поэтому для него написан
   `scripts/tls-terminating-relay.mjs`: Node устанавливает TLS 1.3-соединение с
   origin (**с полной проверкой сертификата**) и отдаёт трафик браузеру по
   локальному каналу. Проверка сертификата gravity.nl выполнена, но в Node, а не в
   браузере.
2. **GPU.** Рендеринг — SwiftShader (программный). Всё, что зависит от реального
   GPU, ниже помечено отдельно.
3. **dna.inc — сцена первого экрана визуально не снята.** Подробности в разделе 3;
   это не «не пробовали», а зафиксированное поведение сайта.
4. **Cookie-баннеры** перекрывают часть первых экранов (`lightbase`, `gravity`,
   `globalorange`) — они видны на скриншотах и учтены при чтении композиции.

## 1. DNA.inc — `https://www.dna.inc/`

**Статус:** 200. Скриншоты: `research/references/dna-inc/`, включая отдельный
углублённый прогон (`intro-*.png`, `scroll-*.png`, `no-webgl.png`, `deep-dive.json`).

### Главный результат разбора

Сайт **полностью закрыт вступительной сценой**. В DOM присутствует
`div.intro-container` — `position: fixed`, `z-index: 20`, сплошной чёрный фон,
`1440 × 900`, `opacity: 1`. Одновременно корневой контейнер Lenis имеет класс
`lenis-stopped`: прокрутка программно заблокирована.

Мы держали страницу открытой **30 секунд**, кликали, двигали курсором, пробовали
`waitUntil: 'load'` — состояние не изменилось ни разу:

```
5s  {"intro":"1/flex/visible","lenis":"lenis lenis-stopped","gl":"has-ctx"}
30s {"intro":"1/flex/visible","lenis":"lenis lenis-stopped","gl":"has-ctx"}
```

WebGL-контекст при этом **создаётся успешно** (`webgl2`), canvas получает полный
размер вьюпорта (desktop `1440 × 900` при DPR 1; mobile `390 × 844` CSS против
`780 × 1688` буфера, то есть DPR ограничен двойкой). То есть дело не в отсутствии
WebGL, а в том, что снятие интро завязано на готовность/прогресс сцены, которая на
программном рендерере не достигает нужного состояния.

**Вывод, который мы применяем к себе:** содержимое сайта не должно зависеть от
завершения 3D-сцены. Это главный урок из основного референса, и он получен
эмпирически.

### Композиция и типографика (из DOM, не из картинки)

* Шрифты: `Neue Haas Unica` (интерфейс/текст), `Haas Grotesk Display` **weight 900**
  для крупных заголовков, `Denton` (контрастная антиква) весом **100–300** для
  «мягких» заголовков. То есть два регистра голоса: тяжёлый гротеск для
  утверждений, тонкая антиква для рефлексии.
* Шкала: H2 53.4 px / weight 900 / трекинг +0.01em; отдельный H2 64.5 px / weight 100
  (Denton). Крупная типографика, но не гигантская.
* Ритм секций: подряд идут `section` с `background: rgb(255,255,255)` и
  `background: rgb(0,0,0)` — подтверждённое чередование светлых и тёмных блоков.
* Токены: `--header-height`, `--global-side-pad`, `--color-primary`, `--color-bg` —
  очень компактный набор переменных, а не «дизайн-система на 200 токенов».
* DOM всего **406 узлов** — страница очень лёгкая по структуре.
* Переходы: 0.15 s / 0.2 s / 0.3 s / 0.4 s, преимущественно `linear` и `ease-out`.

### Без JavaScript

`desktop-nojs.png` тоже чёрный, **но текст в DOM присутствует** (2247 символов,
корректный `h1`). Контент индексируется, однако визуально пользователь без
работающей сцены не получает ничего.

## 2. Gravity — `https://gravity.nl/`

**Статус:** 200 (через TLS-терминирующий релей). Скриншоты: `research/references/gravity/`.

* **Позиционирование:** «AI Powered Platforms», надзаголовок
  `— GRAVITY — SIMPLICITY STARTS HERE`. Первый экран — полноэкранная фотография
  рабочего процесса с тёмным градиентом, поверх неё крупный светлый заголовок и две
  кнопки: заполненная янтарная (`Bekijk ons werk`) и контурная (`Plan een
  kennismaking`). Ровно тот приём «одна яркая + одна контурная», который мы берём.
* **Типографика:** `Instrument Sans`. H2 35.3 px weight 500 с трекингом **−0.025em**.
  Крупный hero-заголовок — светлый, очень широкая межстрочная плотность. Надзаголовки
  набраны капителью с положительным трекингом.
* **Технологии:** Nuxt (`/_nuxt/` в запросах) — confirmed; Cloudflare — confirmed;
  Lenis (`window.lenis`) — confirmed. Canvas/WebGL **отсутствует** — весь эффект
  сделан фото + типографикой.
* **Motion:** самое интересное место всей выборки. В инлайновом CSS присутствуют
  `@keyframes page-enter` / `fade-out` с `--spring-duration` и `--page-easing`, а
  переходы описаны **`linear()`-функцией с 30+ контрольными точками** — то есть
  пружинная кривая, аппроксимированная средствами CSS. Дополнительно есть блоки
  `@supports (animation-timeline: scroll(root block))` — scroll-driven анимации
  на нативном CSS, без JS.
* **Доступность motion:** переходы страниц обёрнуты в
  `@media (prefers-reduced-motion: no-preference)`, а в
  `@media (prefers-reduced-motion: reduce)` стоит `animation: none !important`.
  Это образцовая реализация, и мы её повторяем по смыслу.
* **Sticky:** 6 элементов `position: sticky` — секции с закреплённым текстом.
* **Без JS:** заголовок и 2396 символов текста присутствуют.

## 4. Lightbase — `https://lightbase.nl/diensten`

**Статус:** 200. Скриншоты: `research/references/lightbase/`.

Это единственный референс, где мы смотрели **именно страницу услуг**, и он самый
близкий к нашей задаче по структуре.

* **Композиция первого экрана:** тёмный фон `rgb(33,33,33)`, слева гигантский H1
  **96 px** (`haffer`, weight 400, трекинг normal) — одно слово «Diensten», справа
  в узкой колонке — абзац-объяснение. Асимметрия «огромное слово + маленький текст
  сбоку» работает очень хорошо и берётся нами как приём.
* **Структура услуг:** пронумерованные карточки `01 / 02 / 03` с курсивными
  номерами, заголовком и абзацем. Три этапа: «Onderzoek en advies» → «Ontwerp en
  ontwikkeling» → «Beheer en doorontwikkeling». Это подтверждает, что группировка
  услуг по жизненному циклу — рабочий паттерн, а не наша выдумка.
* **Цвет:** один акцент — светлый периwinkle `#B8B4F5` — используется как заливка
  крупного CTA-блока и кнопок, никогда как мелкий текст на светлом.
* **Технологии:** Next.js (`/_next/` в запросах) — confirmed. Tailwind — likely
  (единственная CSS-переменная `--tw-font-weight`). Canvas нет.
* **Motion:** очень сдержанный — 0.1 / 0.2 / 0.5 s с `cubic-bezier(0.4, 0, 0.2, 1)`.
* **DOM 273 узла** — самая лёгкая страница выборки при насыщенном контенте.

## 5. Bravoure — `https://bravoure.nl/en`

**Статус:** 200. Скриншоты: `research/references/bravoure/`.

* **Первый экран:** чистый белый, огромный чёрный заголовок `Manrope` **88 px,

  цветной 3D-рендер (шёлковые ткани, сфера) во всю ширину экрана.
* **Приём, который мы адаптируем:** контраст «спокойная типографическая верхняя
  половина + резкий визуальный удар во всю ширину сразу под ней». Это даёт
  ощущение уверенности без визуального шума в самой важной зоне.
* **Меню:** свёрнуто в иконку даже на десктопе (1440 px) — только логотип слева и
  бургер справа. Смелое, но спорное решение (см. «Отклонённые решения»).
* **Технологии:** Framer (`generator=Framer 80b8aa5`, `server: Framer/...`) —
  confirmed. Canvas нет: визуал — это заранее отрендеренное изображение, а не
  реалтайм-3D. Важное наблюдение: **ощущение 3D достигается статичным рендером.**
* **Motion:** одна кривая на весь сайт — `0.4s cubic-bezier(0.44, 0, 0.56, 1)`.
  5 элементов `position: sticky`.

## 9. Общие паттерны выборки

1. **Крупная типографика с отрицательным трекингом.** 64–96 px для H1, трекинг от
   −0.02em до −0.04em (bravoure −0.02em, yummygum −0.04em, gravity −0.025em).
2. **Надзаголовок капителью** над крупным заголовком — 5 сайтов из 7.
3. **Очень мало CSS-переменных.** DNA.inc — 7 штук. Никто не строит гигантскую
   систему токенов.
4. **Лёгкий DOM.** 273–962 узла. Медиана ~500.
5. **Один акцентный цвет** на сайт: янтарный (gravity), оранжевый (duodeka,
   globalorange), периwinkle (lightbase), розовый (yummygum).
6. **Реальный WebGL — редкость.** Только 2 из 7 имеют canvas, и лишь у DNA.inc он
   несёт смысл. Bravoure добивается «трёхмерности» **статичным рендером**.
7. **Контент присутствует без JS** у всех семи (1092–2396 символов текста).
8. Длительности переходов группируются вокруг **0.2 s** (мелкие интерактивы) и
   **0.4–0.8 s** (появление блоков).

## 10. Противоречия между референсами

| Вопрос | Одна позиция | Противоположная | Наше решение |
| --- | --- | --- | --- |
| Меню на десктопе | Bravoure прячет всё в бургер | Lightbase, Gravity, GlobalOrange показывают 5–7 пунктов | Показываем пункты на десктопе; бургер только на мобильном |
| Тяжесть motion | DNA.inc: GSAP + Lenis + swup + three.js | Duodeka, GlobalOrange: только CSS-переходы | Середина: CSS-reveal по умолчанию, JS-анимация точечно |
| Плавный скролл | Lenis у DNA.inc и Gravity | Остальные пять — нативный скролл | **Нативный скролл.** Lenis ломает доступность и не окупается |
| Роль 3D | DNA.inc: реалтайм-сцена | Bravoure: статичный рендер | Реалтайм-сцена, но с обязательным статичным постером-фоллбэком |
| Скругления | Yummygum: скругления везде | DNA.inc, Lightbase: прямые углы | Прямые углы для секций, небольшое скругление только у интерактивных элементов |
| Показ результатов | Yummygum выносит цифры в список | DNA.inc не показывает цифр вовсе | Показываем, но только реальные и с методикой измерения |

## 11. Принятые решения

* Полноэкранный `100svh` hero с оригинальной WebGL-сценой — **поверх которой всегда
  лежит настоящий HTML-текст**, отрисованный сервером.
* Нативный скролл. Никакого scroll hijacking и никакого smooth-scroll-движка.
* Чередование тёмных и светлых секций как ритмическая основа страницы.
* Один акцентный цвет, применяемый по строгому правилу (см. `docs/design-system.md`).
* Motion-система из токенов длительностей и кривых, включая пружинную кривую по
  мотивам приёма Gravity; полное отключение при `prefers-reduced-motion`.
* Измеримые результаты в карточке кейса с обязательным полем «как измеряли».
* Фильтры-пилюли + поиск, синхронизированные с URL query params.

## 12. Отклонённые решения

* **Интро-оверлей и блокировка скролла** — прямой урок из DNA.inc.
* **Lenis / кастомный движок скролла** — вред для доступности и клавиатуры.
* **Бургер-меню на десктопе** — прячет навигацию без выигрыша.
* **Кастомный курсор** (DNA.inc) — на touch бесполезен, на desktop мешает.
* **Капслок weight 900 для длинных заголовков** — кириллица набирается длиннее
  латиницы, капслок ухудшает читаемость.
* **Скруглённая карточка вокруг каждого блока** — превращает страницу в список плашек.
* **Плавающие кнопки и cookie-баннеры поверх первого экрана.**
* **Лента логотипов прессы / клиентов** — у студии нет подтверждённых публикаций,
  выдумывать их нельзя.

## 13. Собственная дизайн-концепция «Серая Мышь»

**Идея:** серый мир, в котором есть один сигнал.

Студия называется «Серая Мышь» — незаметность здесь не недостаток, а метод:
внимательная работа без самолюбования. Визуально это переводится так: почти вся
палитра — графит и холодные серые, и ровно один цвет — **сигнальный лайм** —
отмечает то, что действительно важно: активное состояние, результат, действие.

Отсюда же название 3D-объекта — **Grey Signal**: графитовая масса, внутри которой
проходит сигнал.

Тон: спокойный, точный, с сухой иронией. Ни одного из запрещённых штампов.

## 15. Motion-концепция

* **Токены:** `--dur-quick 160ms`, `--dur-base 320ms`, `--dur-slow 640ms`,
  `--dur-reveal 720ms`; кривые `--ease-out`, `--ease-in-out`, `--ease-spring`
  (аппроксимация пружины через `linear()`, приём подсмотрен у Gravity),
  `--stagger 60ms`, `--reveal-distance 18px`.
* **Брендовый приём:** *signal sweep* — при появлении блока по нему один раз
  проходит тонкая горизонтальная сигнальная линия, после чего проступает текст.
  Один приём, применяемый последовательно, вместо анимации всего подряд.
* **Reveal:** `IntersectionObserver` + CSS-переход `opacity`/`translateY`, без
  JS-анимации на кадр. Элемент анимируется один раз.
* **Hover:** только `transform` и `opacity`, 160 ms.
* **Фильтры:** смена выдачи через `AnimatePresence`, не мешает клавиатуре.
* **Reduced motion:** `IntersectionObserver` не вешается вообще, все элементы
  сразу видимы, 3D-сцена переходит в статичный кадр.

## 16. План 3D-сцены Grey Signal

* Чистый three.js (без React Three Fiber) — одна сцена, полный контроль над
  циклом рендера и DPR. Обоснование в `docs/decisions.md`.
* Геометрия создаётся программно: икосаэдр высокой детализации, вершины смещаются
  доменно-искажённым шумом (собственный GLSL-шейдер), вокруг — облако частиц на
  `Points` и несколько тонких линий-«усов» на `LineSegments`. Силуэт даёт лёгкий
  намёк на два «уха» без буквального маскота.
* Материал: физически-правдоподобный металл (графит) с тонким контурным
  подсветом; сквозь массу проходит узкая полоса акцентного цвета — тот самый
  «сигнал».
* Освещение: два направленных источника + мягкий ambient, без теней.
* Постобработка отсутствует — она удваивает стоимость кадра и не нужна.
* Взаимодействие: демпфированное смещение камеры за указателем, очень медленное
  idle-вращение, scroll-driven уход объекта вглубь и растворение к следующей секции.
* Адаптивность: DPR ограничен 1.75, на мобильных — 1.5; количество частиц и
  детализация геометрии снижаются по ширине экрана; при `prefers-reduced-motion`
  рендерится один статичный кадр; вне вьюпорта и при скрытой вкладке цикл
  останавливается; обрабатывается `webglcontextlost`.
* Fallback: `public/hero-poster.jpg` — постер, отрендеренный **из этой же сцены**
  (`scripts/render-hero-poster.mjs`), показывается при отсутствии WebGL.

## 17. Риски производительности

| Риск | Причина | Меры |
| --- | --- | --- |
| 3D задерживает LCP | Бандл three.js + компиляция шейдеров | LCP-элемент — HTML-заголовок, отрисованный сервером; сцена грузится `next/dynamic` с `ssr: false` после первого кадра |
| Высокий DPR на мобильных | Retina × полноэкранный canvas | Ограничение DPR (1.75 desktop / 1.5 mobile) |
| Постоянная нагрузка на GPU | Бесконечный `requestAnimationFrame` | Пауза по `IntersectionObserver` и `visibilitychange` |
| Потеря контекста WebGL | Фоновые вкладки, слабые GPU | Обработчик `webglcontextlost` → показ постера |
| Тяжёлые изображения кейсов | Полноэкранные превью | Payload `imageSizes` + `next/image` + AVIF/WebP + корректные `sizes` |
| Layout shift | Изображения и шрифты | Фиксированные `aspect-ratio`, `next/font` с `display: swap` и метриками фоллбэка |
| Раздувание клиентского JS | Библиотеки анимации | Reveal на CSS + `IntersectionObserver`; JS-анимация только для меню и фильтров |
| CLS от cookie-баннера | Наблюдалось у трёх референсов | Баннера нет; аналитика подключается только при заданном ID |
